# M6 施工清单：调研验证器（立题 / GitHub 取证 / 四判定 / 回写）

> 目标（README 里程碑表 + 方案 §3.6）：出单、生成方案之后，拿确认单里的几个问题去 GitHub
> 查「这件事别人做过没、被抱怨过什么、坑在哪」，产出一份**敢说没人做过**的验证报告，
> 结论只能进第 2/5 栏。
>
> 一句话边界：**证据不参与塑造你的方案，只检验它是否站在空地上。**
> 所以调研排在最后，且调研结果不回灌提问引擎——AI 不许因为查到过别人的做法而少问你问题。

---

## 1. 范围与不做

做：

- `research` / `verdict` / `research_cache` 三张表（库 v3 → v4 显式迁移）。
- **立题**：从确认单 + 问答抽 3~6 个可检索问题（模型起草，用户可删可改；模型不可用时规则兜底）。
- **取证**：GitHub Search API（repo / issue / code）+ README 原文抓取；PAT 可选；代理/镜像 base 可选。
- **对照**：拿这次的问题、原话、五栏单和证据摘要，让模型产出四判定；
  机械层做白名单过滤与四条硬规则（见 §3.4）。
- **报告**：坏消息在最前、顶部「证据覆盖 N/M」、无人区必须附已覆盖关键词、失败逐条可见。
- **回写**：结论进第 2 栏（既成事实）与第 5 栏（没验证过的风险）；第 3 栏**结构上进不去**。
- **出口**：报告 .md 落盘（SAF，复用 M5）+ 系统分享；**离线外包**（导出提示词 / 粘回结果）。
- **设置**：GitHub PAT（Keystore）、代理 base、通用复核开关、隐私告知（关键词会明文发出去）。

不做（写清理由，免得以后反复）：

- **不自动跑**：这是「偶尔做一次的重活」（约 6~14 次 API 调用 + 一次 4~8k token 的对照），
  放成按钮，不进主流程。
- **不做外部搜索引擎**：方案 §3.6.1 的「非 GitHub 补充源」在手机上要再加一个不受控的第三方抓取面，
  收益不抵风险。**改为「换词复核」**：判定无人区时，用「原句 + 关键词单发」再检索一遍，
  仍然 0 命中才算无人区，否则降级「未取证」（见 §3.5）。
- **不把证据写进 `sheet_item`**：见 §3.1 的决策 3。
- **不做定时/后台调研**、不做多轮追问式检索、不抓源码全文（只抓 README/文档 markdown）。
- **不做「别人都这么做所以你也这么做」**：报告里不产出选型建议，只产出「有没有人做过 / 被抱怨什么」。

## 3. 关键决策

1. **顺序铁律不靠自觉，靠结构**：`AppliedTo` 枚举里根本没有 `COL3`；`verdict.appliedTo` 在库里有
   `CHECK (appliedTo IN ('col2','col5','appendix'))`。UI 里也只有「进约束」「进待决」「只进附录」三个开关。
2. **调研不回流引擎**：`EngineContext` 不读 `research`。证据只能在出单之后出现，
   这样「查到东西就少问问题」这条路在代码上不存在。
3. **证据不进 `sheet_item`**（本里程碑最重要的取舍）：
   `sheet_item.sourceMessageIds` 的语义是「这句话来自我说的哪句原话」，docs/05 §3 有硬门
   （`sourceMessageIds='[]'` 必须 0 行）。证据的出处是 **URL**，不是我的原话——
   插进去就会把「每条结论都可追溯到你」这条 M1 立下的规矩稀释成「有的能追溯、有的不能」。
   所以：
   - `verdict` 表存结论 + 被引用的原文 + URL；
   - 确认单页在**第 2 栏、第 5 栏下方**各挂一块只读的「调研补充」，点一条跳到原始 issue；
   - **导出物里并列到那两栏**：复制为提示词与导出 .md 的第 2/5 栏下面多一个「调研补充（带链接）」小节，
     六行模板标题不变。
4. **一次调研 = 一行 `research` + N 行 `verdict`**：报告是渲染产物，但**判定要能按条回写/撤销**，
   而 `applied_to` 又要数据库约束守着铁律，所以 verdict 拆表；证据摘要与原始链接存在 verdict 行里
   （证据只在判定时被读，没有跨查询需求）。
5. **取证层用接口隔开网络**：`HttpFetcher` 是纯接口，`GitHubClient` 的所有纪律
   （12s/25s/30s、退避 2 次、4xx 不重试、部分成功、白名单、代理回退）都能在 JVM 单测里用假 fetcher 验，
   不用真网。真网只在真机验收里出现。
6. **超时纪律照方案 §3.6.3 七条落**：一轮 60s 硬上限、到点用手里的结果出报告；
   部分成功是正常态（`status=partial`）；**失败必须可见**（每个失败问题一行 ❌ + 原因）。
7. **PAT 三条红线**：只在 `SecretStore` 出现明文；只发白名单 host（`api.github.com` 与用户填的代理域）；
   `raw.githubusercontent.com` 与其它域一律不带；UI 只显示后 4 位；「清除」连带清内存里缓存的 header。
8. **code search 匿名不可用**：没有 PAT 时直接跳过并记 `Failure("代码检索需要 token")`，
   报告里如实写「这一类证据没查」，**不假装查过**（静默失败的「无人区」是有害的）。
9. **「无人区」硬闸**：判定 unexplored 必须 ① 覆盖关键词非空 ② 做过换词复核 ③ 复核仍 0 命中；
   缺任一条 → 降级 `UNGATHERED`，报告文案「这次没查够，不下结论」。
10. **规则兜底也要能用**：模型挂了/没网时，立题从五栏单的第 2/5 栏与场景题里抽关键词；
    取证照跑；对照跑不了就把证据整理成「原始证据清单」报告（`status=partial`），仍然可导出。
11. **离线外包（降级第 4 条）**：把立题结果 + 取证要求打包成一段提示词，复制/分享到桌面端；
    用户把 JSON 粘回来走同一套解析与校验（`source=OFFLINE`），结论一样进库。
12. **缓存 24h 按「端点+查询」**：同一份确认单重跑不该再打网络（GitHub 匿名 Search 限流 10 次/分钟）。

## 4. 施工顺序

- S1 域层纯函数（模型 / 立题兜底 / 证据解析 / 四判定规则 / 报告 Markdown）+ 单测（先测后写）

## 7. 风险

| 风险 | 处理 |
|---|---|
| 「无人区」误判（最有害） | 三条硬闸 + 覆盖关键词必列 + 复核开关；不满足一律降级「未取证」 |
| 证据被模型编造 | evidence id 白名单；`quoted_url` 必须是这次真抓到的 URL；对不上就丢该条判定 |
| 调研污染决策 | 枚举里没有 COL3 + 库 CHECK + 导出物只在第 2/5 栏 |
| 直连超时（用户的现实条件） | 60s 硬上限 + 部分成功 + 缓存 + 代理回退 + 离线外包 |
| 匿名限流 10 次/分钟 | 每轮问题数 ≤6、每类一次调用、24h 缓存；超了记失败原因不重试 |
| PAT 泄露 | 只进 SecretStore；只发白名单 host；UI 后 4 位；日志与导出一律不带 |
| 报告变成「一堆链接」 | 四判定 + 每条判定必带一句「意味着什么」；空判定丢弃（宁可少一条结论） |

## 8. 施工期补充决定（动工后想清楚的，回头补在这里）

1. **`appliedTo` 由机械层分配，不听模型**：反模式/常见做法 → 第 2 栏；已知坑/无人区 → 第 5 栏；
   未取证 → 只进附录。模型只负责「看出来」，落点由代码定——它没有「把结论塞进第 3 栏」的通道，
   用户在页面上也只能在「第 2 栏 / 第 5 栏 / 只进报告」三者之间切（`ResearchRules.defaultAppliedTo`）。
2. **复制为提示词不带调研结论（故意的）**：提示词是给下游模型干活的，
   把「别人怎么做」塞进去，正是方案 §八 要防的决策污染。结论留在确认单页的「调研补充」区块与报告里，
   给自己看、给同事看，不给下游模型当依据。所以 M1 的六行模板**逐字不变**（`PromptExporterTest` 继续锁着）。
3. **「通用搜索复核」换成「换词复核」**（§1 已写不做外部搜索引擎）：判定无人区时用「原句 + 关键词单发」
   再检索一遍 GitHub；仍然 0 命中才算无人区。理由：多一个不受控的第三方抓取面，收益不抵风险，
   而且「换词再查」才是这条结论真正需要的证据（同一个词搜不到可能只是词没搜对）。
4. **离线外包的契约要求「证据 + 判定」一起回**：只回判定的话，手机上会出现「引用了不存在的链接」——
   那比没有报告更糟。`OfflineResearch.promptOf` 里把两部分格式都写给了桌面端。
5. **对照的证据上限 40 条**（`PromptBuilder.maxEvidenceInContext`）：手机端 token 与内存都不适合喂全量；
   超出的在上下文里明说「还有 N 条没列出来，已省略」，不假装全给了。
6. **`research_cache` 落库而不是放内存**：进程被杀之后同一份确认单重跑不该再打网络（匿名每小时 60 次）；
   每次调研开始时顺手清 24h 之前的行，不做定时任务。
7. **code search 匿名直接跳过**（§3.8 已写）：GitHub 的硬规定，跳过一次都不打，报告里如实留一行。
