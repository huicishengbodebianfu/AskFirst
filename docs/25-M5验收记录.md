## 4. 真机上发现并修掉的缺陷（验收驱动）

1. **SAF 写入抛 `Invalid URI`**：`DocumentsContract.createDocument` 必须给「父目录的 document uri」，
   直接把 tree uri 塞进去时，AOSP `ExternalStorageProvider` 拒绝（M5-08 第一轮「存不进去：Invalid URI: …」）。
   修复：`buildDocumentUriUsingTree(treeUri, getTreeDocumentId(treeUri))` 作为父目录；失败文案也改成人话。
2. **blocking 文案在页面上出现两遍**（红卡一次、消息行又一次）。修复：`Done` 且 `!canSend` 时不再重复写消息行，
   只留红卡；「先出了一部分，还差 N 节」只在非 blocking 时出现。
3. **方案页在没有方案时场景名显示成「这场思路」**：`planViewOf` 没方案就返回 null，页面拿不到场景名。
   补 `facade.sceneNameOf(sessionId)`，没方案也能显示「技术方案 · 架构选型」。

顺带（M4 核查，见 docs/23 §8）：空摘要把引用摘要注入成空尾巴，三条 SQL 的 `NULLIF` 只作用在第一个表达式。
本轮把这条**直接坐实**了——假引擎抓到的请求体里引用段是：

```
## 引用的旧确认单摘要（只作背景，不许拿它替他回答）
- [scene_7d3e6b279a8141ae] 首屏缓存分层
- [scene_tech_arch] 首屏缓存分层
- [scene_tech_arch] 首屏 4 秒太慢，想加缓存      ← 修之前这一行是空的
```

## 5. 决策与偏差

1. **一场会话一份方案，不留版本历史**：确认单才是真相来源，方案是它的渲染；多版本只会让人分不清哪份是准的。
2. **骨架不从代码里写死**：直接用 `scene.planSkeleton`（M1 就入库的列，M3 的复制/导入导出已带着走）。
   M5 不加骨架编辑入口——自建场景要换骨架就编辑它的 JSON（M3 的路已经通）。
3. **续写不复用半截 JSON**：把已生成章节的标题交给模型、只补缺章。比流式半截解析可靠，用户也看得懂「还差 3 节」。
4. **本体不装进草稿**：续写请求里只给已有章节的**标题**，不给正文（少 token，也避免模型顺手重写）。
5. **硬答案保护只做数字/日期**：「否定式不软化」判断噪声太大，交给提示词约束 + 人工预览（docs/24 §1 明确不做）。
6. **假引擎的标题是硬编码**：真机验收里自建场景的文档标题也显示「首屏缓存分层方案」，这是 `tools/fake_sse_server.py`
   的假 payload，不是 App 的行为；真模型会给它自己的标题（`title` 缺省时才回落开题句）。
7. **既有 M2 行为，未在 M5 动**：历史详情页从详情返回时用的是缓存状态（消息数不刷新，列表页是实时的）。
   与本里程碑无关，记进 §7 待办。
8. **冷启动门槛**：docs/05 §3 的 `TotalTime < 800ms` 是 M0 空壳时测的，现在真实体量是 1.7~1.9s。本轮不动代码，
   把门槛按现状校准为 `< 2500ms`（见 docs/05 §3 备注）。
9. **设备上一度为 18:07 版的过渡状态已解决**：复核阶段重试 `adb install -r` 直接成功（18:41），
   设备现在跑的就是 HEAD 版；此前那次是荣耀「安全模式」确认弹层（复选框 + `继续安装` → 底部弹层的
   「允许本次安装」）把安装停在人工确认上，属系统侧确认，不是包的问题。原来那条「纯文案去重未真机复验」
   的保留意见随之作废——复核时已看到红卡只出现一次（见 §8.2 M5-04b）。

### 8.3 复核中新发现并修掉的两个缺陷

1. **零消息会话生成方案 → 提示牛头不对马嘴**（P2）
   真机现象：一场「0 条消息」的会话点「生成方案」，页面说
   「模型这次没按格式回：每一段都对不上原话（出处全是编的）…点重试再试一次」——
   真正原因是**这场还没聊过**，而且方案页根本没有「重试」这个按钮。
   修：① 门面短路——`turns` 为空直接给「这场还没聊过，没有可溯源的原话。先聊两轮，再来生成方案。」；
   ② 新增 `AppError.PlanRule`（文案即成品），把方案页的 `BadJson` 文案换成它上面真有的三个按钮的说法
   （「接着写剩下的」或「重新生成整份」），不动提问流/出单那句通用文案。
2. **同一标题写两遍会存成两节**（P3）
   模型偶尔把「约束」写两次，页面就会长出两个「3. 约束」。
   修：解析时按标题去重（复用 `PlanSkeleton.matches`，与续写合并同一套判定），并补 1 个单测。
