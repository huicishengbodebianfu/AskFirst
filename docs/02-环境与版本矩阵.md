# AskFirst 环境与版本矩阵（M0/M1 施工基线）

> 目标：在这台机器上一次装好、长期可复现，并且**任何一步都不许把文件写到 C: 盘**。
> 本文所有命令都在 `pwsh` 里执行。

---

## 1. 为什么工程不在 `F:\安卓\` 里直接构建

本机工作目录是 `F:\安卓`（含中文）。AGP / Gradle 在 Windows 上对非 ASCII 绝对路径存在编码不一致问题
（历史验证：`java.util.Properties.load` 按 ISO-8859-1 读 `local.properties`，中文路径被解成 `F:\å®å\…`，
报 `Included build '…' does not exist` 之类远端错误）。因此沿用本机既有约定：

```
真实工程目录   F:\安卓\AskFirstApp
构建用 ASCII 别名  F:\askfirst   →  NTFS junction  →  F:\安卓\AskFirstApp
```

重建 junction（不需要管理员，不占空间）：

```powershell
cmd /c mklink /J F:\askfirst "F:\安卓\AskFirstApp"
```

**规矩：所有 `gradlew` / `adb` / IDE 打开动作都走 `F:\askfirst`；`F:\安卓\AskFirstApp` 只作为真实落盘位置。**

## 3. 一键环境脚本

`F:\安卓\.android-build\askfirst-env.ps1`（已创建）：

```powershell
. 'F:\安卓\.android-build\askfirst-env.ps1'
cd F:\askfirst
```

脚本做的事（逐条都是「防落 C 盘」或「防编码坑」）：

| 变量 | 值 | 为什么 |
|---|---|---|
| `JAVA_HOME` | `F:\安卓\.android-build\jdk\jdk-17.0.20.1+1` | 覆盖系统里那个 jre-8 |
| `ANDROID_HOME` / `ANDROID_SDK_ROOT` | `F:\asdk` | SDK 在 F: |
| `ANDROID_USER_HOME` / `ANDROID_AVD_HOME` | `F:\安卓\.android-build\.android` / `…\avd` | adb/AVD 元数据不落 C: |
| `GRADLE_USER_HOME` | `F:\gh`（ASCII 联接 → `F:\安卓\.android-build\gradle-user-home`） | 依赖缓存与 wrapper dists 不落 C:；**且路径必须是 ASCII**（见 §6 的 worker 事故） |
| **`TEMP` / `TMP`** | `F:\安卓\.android-build\temp` | 最关键：Gradle/Kotlin 守护进程、AGP 解压 aapt2 都走 TEMP |
| `JAVA_TOOL_OPTIONS` | `-Dfile.encoding=UTF-8 …` | 本机 JVM 默认 GBK，中文源码/日志会乱码 |
| `PATH` | 前置 JDK bin、platform-tools、cmdline-tools | 避免命中 C: 上旧 adb/java |

**自检 C 盘零写入**：

```powershell
# 这三个目录若出现新内容，说明有工具没吃到环境变量
Get-ChildItem "$env:USERPROFILE\.gradle"        -ErrorAction SilentlyContinue
Get-ChildItem "$env:USERPROFILE\.android"       -ErrorAction SilentlyContinue
Get-ChildItem "$env:USERPROFILE\AppData\Local\Temp" -ErrorAction SilentlyContinue | Measure-Object
```

### 为什么 Room 用 KAPT 而不是 KSP

KSP 的坐标版本在 2026 年已改成与 Kotlin 解耦的 `2.3.x` 线，本机缓存里没有与 Kotlin 2.2.20 对齐的
KSP 产物，而 KAPT 随 Kotlin Gradle 插件一起提供、零额外下载。M1 只有 6 个实体，KAPT 的构建开销可以接受。
**M2 起若构建变慢，再评估迁移 KSP（届时用真实构建实测版本匹配，不要凭猜）。**

## 6. 构建命令

```powershell
. 'F:\安卓\.android-build\askfirst-env.ps1'
cd F:\askfirst

# 日常
.\gradlew.bat :app:assembleDebug
.\gradlew.bat :app:testDebugUnitTest          # 纯 JVM 单测（引擎/解析/状态机）

# 装机（真机）
& 'F:\asdk\platform-tools\adb.exe' -s <设备序列号> install -r .\app\build\outputs\apk\debug\app-debug.apk
& 'F:\asdk\platform-tools\adb.exe' -s <设备序列号> shell am start -W -n com.askfirst/.MainActivity

# 看崩溃
& 'F:\asdk\platform-tools\adb.exe' -s <设备序列号> logcat -b crash -d
```

### 常见故障对照

| 现象 | 原因 | 处置 |
|---|---|---|
| `SDK location not found` | 走了中文路径 / local.properties 少了转义 | 用 `F:\askfirst`；`sdk.dir=F\:\\asdk` |
| `Unsupported class file major version` | 用到了 C: 上的 JDK 8/17.0.12 | 先 source 环境脚本，`java -version` 应为 17.0.20.1 |
| 依赖 404 | 镜像缺该坐标 | 临时把 `google()`/`mavenCentral()` 提到前面重试，成功后记进本文 |
| `Cannot use @Composable` 之类 | Compose 编译器插件版本 ≠ Kotlin 版本 | 两者都必须是 2.2.20 |
| 构建特别慢 | Gradle 守护进程被 TEMP=C: 影响，或默认仓库超时 | 检查 TEMP；仓库顺序按第 4 节 |
| `Gradle build daemon disappeared unexpectedly` + `hs_err_pid*.log` 里 `Failed to commit metaspace` | `-Xmx3072m` + Kotlin daemon + kapt 把 native 内存吃光 | 降到 `-Xmx2048m -XX:MaxMetaspaceSize=896m`，`parallel=false`，`workers.max=2`，Kotlin daemon `-Xmx1280m`（已写进 `gradle.properties`） |
| 单测子进程 `找不到或无法加载主类 worker.org.gradle.process.internal.worker.GradleWorkerMain` | **`GRADLE_USER_HOME` 是中文路径**：Gradle 用 UTF-8 写 `@argfile`，Java launcher 用 `sun.jnu.encoding=GBK` 读 → 路径乱码 | 用 ASCII 联接 `F:\gh` 指到缓存目录，环境脚本里 `GRADLE_USER_HOME=F:\gh`；联接不复制文件，缓存原地复用 |
| 改一个文件后报一堆 `Unresolved reference`（符号明明存在），`clean` 后恢复 | Kotlin/KAPT 增量编译缓存被上一次 OOM 崩溃污染 | `gradle.properties` 里 `kotlin.incremental=false` + `kapt.incremental.apt=false`（本项目全量编译 1.5~3 分钟，可接受） |
| 仪器测试 `Starting 0 tests` / `Process crashed`，crash 里有 `UiAutomationService … already registered` | 之前跑过 `uiautomator dump` 且被系统 kill，UiAutomation 注册泄漏 | `adb reboot` 后再跑；HONOR 上 uiautomator 与仪器测试不可共用 |
| 仪器测试全部"连接被拒"（明明起了假服务） | USB 掉线后设备序列号变成 `ip:5555`，而 `adb reverse` 绑在旧 transport 上，映射全丢 | `adb devices` 确认序列号 → 重新 `adb reverse tcp:… tcp:…`；见 `docs/09` §4 |
| 假 SSE 服务让客户端挂 120s | Python `BaseHTTPRequestHandler` 默认 keep-alive，`[DONE]` 后没有 EOF | 响应加 `Connection: close` + `self.close_connection = True` |
| 连自签网关报 `CERTIFICATE_VERIFY_FAILED` / `Trust anchor not found` | release 只信任系统 CA；自签 CA 得装成"用户证书" | 见 `docs/17`：release 装用户 CA；或直接用 debug 包（内置 magpie CA） |
| 点了没反应/一直转圈 | 各层都有预算：ping 20s、测速 30s、单轮 75s、重试 40s、出单 100s | 见 `docs/18`；到点会显示"等了 N 秒没回音"并给重试 |

## 7. 签名（亲友分发，M1 结束前必须做）

不上架，但更新必须能覆盖安装：**签名不一致 = 亲友装不上新版本**。

```powershell
# 一次性生成，放 F: 盘，不入版本库（.gitignore 排除 *.jks / keystore.properties）
& "$env:JAVA_HOME\bin\keytool.exe" -genkeypair -v `
  -keystore F:\安卓\.android-build\askfirst-release.jks `
  -alias askfirst -keyalg RSA -keysize 2048 -validity 10950 `
  -storetype PKCS12 -dname "CN=AskFirst, O=Personal, C=CN"
```

- `keystore.properties`（不入库）：
  ```properties
  storeFile=F\:\\安卓\\.android-build\\askfirst-release.jks
  storePassword=…
  keyAlias=askfirst
  keyPassword=…
  ```
- **备份两处**（网盘 + 手机），丢了就永远发不了更新。
- M1 允许先用 debug 签名自用；**在把 APK 发给第一个亲友之前**切到 release。
