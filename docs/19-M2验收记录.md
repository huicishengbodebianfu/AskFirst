## 5. 偏差与决策

1. **`HistoryRepository.detail()` 未按 docs/01 §7 落地**：详情直接复用门面的 `sessionView()`（M1 已有、真机验过），
   避免 ViewModel 直连仓库的重复路径。接口签名从仓库上移到门面 `history(filter)`。
2. **列表是全量 `Flow`，没有分页**：自用数据量（每天几个会话）远不到分页门槛；M2 后续加导出时再评估。
3. **筛选用 FilterChip 横排而非下拉**：3 个内置场景一屏放得下，少一次弹层。
4. **轮数/条目数用 SQL 子查询**而非读回实体再数——列表滚动时每行只带 10 个字段。

## 6. 环境事故（记录）

- **`adb install` 连续 5 次 `INSTALL_FAILED_ABORTED: User rejected permissions`**：HONOR 的「纯净安装」确认弹窗被
  锁屏盖住（`mCurrentFocus=NotificationShade`），通知栏拉死。解锁 + 弹窗出来后手动「完成」，`Success`。
  规律：**装不上的第一反应先 `dumpsys window | grep mCurrentFocus` 看焦点窗**，再谈别的原因。
- 第一次 `demo_run` 因没填 Key 全部轮次失败（`还差一步：还没填 API Key`）——按 docs/09 的套路
  `adb reverse` + `--es base_url http://127.0.0.1:8083 --es api_key sk-demo` 后跑通。

## 7. 第二步：接着深挖 + 导出 Markdown（同日追加）

### 实现

| 层 | 文件 | 内容 |
|---|---|---|
| 导出 | `domain/sheet/MarkdownExporter.kt` | 纯 Kotlin：整场会话 → `.md`（标题/场景/时间/摘要 + 五栏（空栏写「还没定」、手改条目带「（改）」）+ 问答区块（你/它引用块）+ 尾注）；文件名 `askfirst-<摘要或开题句>-<sessionId尾8位>.md`（中英标点/非法字符全部替换） |
| 门面 | `AskFirstFacade` | `reopen(sessionId)`（done→open，state 回 GATHERING，条目/手改保留）；`exportMarkdown(sessionId)` 返回文件名+正文 |
| UI 详情页 | `HistoryDetailScreen` | open 会话→「继续聊」；done 会话→「**接着深挖**」（点后回退 open 并跳提问流）；「**导出 MD**」按钮 |
| UI 单子页 | `SheetScreen` | 底部按钮行加「导出 MD」（与复制提示词并列） |
| 分享 | 两处 `shareMarkdown()` | `Intent.ACTION_SEND`（`text/markdown`，正文 + 文件名 title）→ 系统分享面板（微信/LocalSend/蓝牙/QQ 等系统级目标） |

导出正文正确性由 `MarkdownExporterTest` 模板逐字锁定（纯函数，同一代码路径），真机验的是「拿得到、发得出去」。

### 决策

- 分享用 `ACTION_SEND` 文本而不是落盘文件：亲友场景（微信发给电脑/朋友）直接贴正文最顺；SAF 落盘留给 M5 方案.md（那边有 `saveToSaf` 接口预留）。
- `reopen` 把 state 拉回 GATHERING 而不是保留 READY：引擎四状态机会按草稿/覆盖重判，READY 停着不会再问。
