## 4. 真机上发现并修掉的一个缺陷（验收驱动）

**搜索 debounce 条件写反，关键词输入永远不触发搜索**：
原写法 `if (kw != _ui.value.keyword) search(kw)`——但 `onKeywordChange` 先把
`_ui.value.keyword` 更新成输入值，debounce 300ms 后到达时两边永远相等，搜索被跳过
（M4-03 第一轮跑的时候列表纹丝不动）。修复：改用独立的 `lastSearched` 记录
「上一次真正拿去搜的词」，与当前输入比较。→ M4-03 这才过滤出 1 行。

这正是「先真机跑一遍才知道」的问题：单测盖不到 ViewModel 的 debounce 时序。

## 5. 决策与偏差

1. **v1→v2 只建 citation 表**：docs/03 原计划 v2 = M2 的 `lastReadAt`，M2 实际没用
   （历史列表用 updatedAt 排序就够），不补空列——少一次无意义迁移风险（施工清单 22 §3 决策 7）。
2. **搜索候选 = 有单子的会话**：没出过单的会话没有可引的结论（s_m3test 无单故不出现）。
3. **LIKE 关键词直接删 `%`/`_`** 而非转义：这两个字符在中文输入里没有正当用途。
4. **选择页结果回传用 `savedStateHandle`**（导航层标准做法），首页消费后清空防重复。
5. **场景删除引用检查无需扩展**（M3 验收 §7 的疑虑）：citation 引用的是 sheet（属会话），
   `countByScene` 拦「会话还在」已保住整条链。
6. **真机中文输入受限**：搜索关键词、intent 用 ASCII 验证流程；中文文案正确性由
   单测与既有文案路径锁定。

### 8.2 复核发现的缺陷（已修）

**P1：空摘要把「旧结论」变成一行空白（候选卡 / 溯源行 / 引擎注入三处都中）**

三条 SQL 都写成
`COALESCE(NULLIF(s.summary, ''), sh.summary, s.intent)` ——
`NULLIF` 只作用在第一个表达式上。真机数据里 `session.summary` 全是 `NULL`
（M1 起就没写这列），而 `sheet.summary` 多是**空串** `''`：

```
NULLIF(NULL,'') = NULL → 取 sh.summary = '' → COALESCE 到此为止（'' 不是 NULL）
```

于是「开题句」这层兜底**从来没生效**。真机可见后果：

- 引用页 5 张卡里 4 张只剩「场景名 + 日期」，两张「技术方案 · 架构选型」长得一模一样；
- 历史详情溯源 3 行里 2 行没有摘要（本文档 §3 M4-08 记的"3 行（含摘要）"其实只有 1 行有字）；
- **更要紧的一条**：`CitationDao.digestsOf` 同一写法 → 引擎上下文里两份引用被注入成
  `- [scene_tech_arch] `（空尾巴）。M4-07 的"已装配"是真的，但**两份引用等于没注入**。

修法（不改变协议）：
1. 三条 SQL 改成 `COALESCE(NULLIF(a,''), NULLIF(b,''), c)`（`SessionDao.searchCitationCandidates`、
   `CitationDao.digestsOf`、`CitationDao.citedEntries`）；
2. 域层补 `CitationPolicy.summaryText(raw, placeholder)`：空白一律给可读占位，
   `CitationRepository` 三处映射都走它（最后一道保险，防将来别的查询再漏）；
3. 补 2 个单测锁这个规则 → 全量 **137/137**。

真机复验：覆盖安装后同一场详情的 3 行变成
「August moving plan」「首屏缓存分层」「首屏 4 秒太慢，想加缓存」——三行都有字了。
