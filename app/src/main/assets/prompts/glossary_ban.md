# 术语黑名单与用词镜像（v1.0.0）

这一份不参与生成，只作为**审查依据**：App 里所有面向用户的字符串（`strings.xml`、提示词、错误文案）
都要按它自检。M1 验收时对 `strings.xml` 与 assets 全文 grep 一遍。

## 1. 绝不许出现在界面上的词

| 词 | 为什么禁 | 该怎么说 |
|---|---|---|
| 门槛 / 门槛未答 | 内部状态机概念 | "还有几件事没聊到" |
| 状态机 / state | 内部实现 | （不出现） |
| 精确度 / 精确度缺口 | 内部检查名 | "这一点还说得比较笼统" |
| 维度 / 收敛 / 闭环 | 咨询黑话 | "哪几个方面" |
| 轮次 / 第 N 轮 | 计数 | "再聊一个" |
| 覆盖 / covered | 内部字段 | "已经聊到的" |
| schema / JSON / payload | 实现细节 | （不出现） |
| 结构化 / 赋能 / 抓手 / 对齐 / 心智 / 沉淀 | 互联网黑话 | 直说动词 |
| 必问 / 选问（作为 UI 标签） | 编辑器内部概念 | "一定会问"（M3 编辑器可保留，但用户侧不显示） |
| 生成中 / 处理中（长时间无内容） | 无信息量 | "正在想……（已收到 12 个字）" |

## 2. 用词镜像表（用户说左边，App 必须跟左边的词）

| 用户说 | 不许改写成 |
|---|---|
| 记一下 / 记 | 录入、登记 |
| 卡 / 慢 | 性能瓶颈、响应延迟 |
| 老是丢 | 数据持久化缺陷 |
| 弄一下 | 实施、落地 |
| 想不清楚 | 需求不明确 |
| 太麻烦 | 流程冗长 |
| 做个东西 | 构建产品 |
| 钱不够 | 预算约束 |

规则：**他的名词优先于你的术语**。技术词只在他先用之后才能用。

## 3. 错误文案要求（三类，都要说人话 + 说下一步）

| 场景 | 文案模板 |
|---|---|
| 网络失败 | "连不上你填的模型地址。检查一下网络，或者回设置看看地址对不对。（重试）" |
| 401 / key 错 | "模型服务不认这个 Key。可能是复制漏了，或者它过期了。（去设置）" |
| 429 / 限流 | "模型服务今天额度用完了（或限流了）。过一会儿再试，或者换一个 Key。" |
| 超时 | "等了 30 秒没回音。可能是网络，也可能是模型太慢。（重试 / 先用本地草稿出单）" |
| 返回的不是 JSON | "模型这次没按格式回。我已经把它的原话留下了，点「重试」再试一次。" |
| 数据灌库失败 | "内置场景没读出来，App 现在不能开始。（重装试试 / 把这条错误发给我）" |

**禁止**："操作失败""系统错误""未知异常""请稍后重试"这类五无文案。

## 4. 首启引导里必须出现的东西（亲友门槛）

- 去哪注册模型服务、在哪充值、在哪创建 API Key、复制哪三个字段（base_url / key / model）；
- Key 只存在本机、不进日志、不进导出文件；
- 模型费用走使用者自己的 Key（不是开发者付）；
- 调研（M6）会把检索关键词明文发给 GitHub，涉及公司未公开项目时不要搜具体业务词。
