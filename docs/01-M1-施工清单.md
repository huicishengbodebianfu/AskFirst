## 0. 一句话范围

**M0（骨架/密钥/流式对话）+ M1（提问引擎 + 3 套场景 + 五栏出单 + 复制提示词）合并施工，
目标产物 = 一个能在我自己手机上跑完一次真实思路确认的 APK。**

M1 结束时**不做**：历史列表以外的长期归档、场景编辑器、跨场景引用、方案.md 生成、调研验证
（分别是 M2/M3/M4/M5/M6）。但 M1 的代码结构必须给它们留好接口（见 §7）。

**M1 必须顺手做掉的两件 M2 事项**（因为它们是"数据一旦丢失就无法补救"的类型）：

- 会话草稿自动保存 + 首页恢复入口（方案 §二："这条必须做，手机上被打断是常态"）；
- 每轮问答落库（否则确认单失去可追溯性）。

### 3.1 唯一门面：`domain/usecase/AskFirstFacade.kt`

```kotlin
class AskFirstFacade(
    private val scenes: SceneRepository,
    private val sessions: SessionRepository,
    private val sheets: SheetRepository,
    private val engine: QuestionEngine,
    private val sheetBuilder: SheetBuilder,
    private val exporter: PromptExporter,
    private val settings: SettingsStore,
    private val clock: Clock,
) {
    suspend fun scenes(): List<Scene>
    suspend fun resumable(): AskSession?                       // 首页"上次未完成"
    suspend fun start(sceneId: String, intent: String): AskSession
    suspend fun session(sessionId: String): SessionView        // session + turns + sheet（首屏渲染）

    /** 提问一轮；answer=null 表示"跳过这题"（跳过也要落库，AI 会换题） */
    fun ask(sessionId: String, answer: String?): Flow<TurnOutcome>

    /** 出确认单（模型一次生成 + 合并已有实时生长内容） */
    fun buildSheet(sessionId: String): Flow<SheetOutcome>

    /** 模型不可用时的本地降级：按已有回答拼骨架，标注未完成 */
    suspend fun fallbackSheet(sessionId: String): Sheet

    suspend fun editItem(sheetId: String, itemId: String, text: String)
    suspend fun exportPrompt(sheetId: String): String

    /** 用户看过了/点了够了 → 状态置 done；随时可以回退 open（M2 用） */
    suspend fun markDone(sessionId: String)
}

data class SessionView(val session: AskSession, val scene: Scene, val turns: List<Turn>, val sheet: Sheet?)

sealed interface TurnOutcome {
    data class Streaming(val chunk: String) : TurnOutcome
    data class Done(
        val turns: List<Turn>,          // 追加之后的完整问答
        val decision: EngineDecision,
        val sheet: Sheet,               // 实时生长后的单子
    ) : TurnOutcome
    data class Failed(val error: AppError, val canRetry: Boolean) : TurnOutcome
}

sealed interface SheetOutcome {
    data class Streaming(val chunk: String) : SheetOutcome
    data class Done(val sheet: Sheet, val check: SheetCheck) : SheetOutcome
    data class Failed(val error: AppError, val canUseFallback: Boolean) : SheetOutcome
}
```

**门面纪律**：ViewModel 不许直接碰 repository / provider / db；`ask()` 内部完成
"组装上下文 → 流式 → 解析 → 状态复核 → 落库 → 生长单子"这一整串，UI 只消费事件。

## 4. 开发顺序（施工步序）

原则：**每一步都能独立跑起来并验收**，不做"全部写完再联调"。S0~S3 是 M0（≈3 天），S4~S7 是 M1（≈5 天）。

| 步 | 内容 | 前置 | 产出文件 | 验收门 | 估时 |
|---|---|---|---|---|---|
| **S0** | 环境与空壳：junction、env 脚本、Gradle wrapper、Compose 空屏装机 | — | `settings/build/gradle.properties/wrapper`、`MainActivity`、theme、manifest、res | `assembleDebug` + 真机启动见到骨架屏 | 0.5d |
| **S1** | 数据层：6 实体 + DAO + DB + 映射 + 三套场景 JSON + 幂等 seed | S0 | `data/db/**`、`data/mapper/**`、`assets/scenes/*.json` | 冷启动后 `sqlite3` 里 3 场景 28 题；`SceneSeedTest` 绿 | 1d |
| **S2** | 设置与密钥：DataStore + EncryptedSharedPreferences + 设置页 + 测试连通 | S1 | `prefs/SettingsStore`、`secret/SecretStore`、`screens/settings/**` | 截图里 key 打码；`logcat` 无 `sk-` | 0.5d |
| **S3** | LLM 通道：OkHttp + SSE + 流式 + 错误映射（401/429/超时/断流） | S2 | `remote/**`、`SseParserTest` | 真机与模型对话，首字 <2s，断网有可读错误 | 1d |
| **S4** | 引擎内核：PromptBuilder + TurnParser + StateMachine + PrecisionGate + Lexicon（**全部纯 JVM**） | S3 | `domain/prompt/**`、`domain/engine/**` | 8 个单测类绿；喂一段假 JSON 能产出 decision | 1d |
| **S5** | 提问流 UI：开题 → 流式 → 一题一卡 → 跳过/够了 → 草稿恢复 | S4 | `screens/home|scene|chat/**`、`usecase/AskFirstFacade` | M1-01~M1-06、M1-11 过 | 1d |
| **S6** | 出单与出口：SheetBuilder + SheetGrower + Validator + PromptExporter + 五栏页 + 剪贴板 | S5 | `domain/sheet/**`、`screens/sheet/**`、`components/**` | M1-07~M1-10 过 | 1d |

### 关键路径与可并行点

```
S0 → S1 → S2 → S3 → S4 → S5 → S6 → S7
              ↘ 提示词文件(engine_system.md/sheet_system.md) 可与 S3 并行写
              ↘ 三套场景 JSON 可与 S2 并行写（内容是抄附录 A）
```

- **S4 之前不要写任何 UI**：引擎的 JSON 契约一变，UI 全废。
- **S3 之前不要写提示词定稿**：先用 5 行临时 prompt 打通流式，再换正式 prompt 调提问质量。
- **S5/S6 可以各切一刀给两个人**（若并行）：分界线是 `AskFirstFacade` 两个方法（`ask` / `buildSheet`）。

### 每步的提交纪律

- 一步一提交，提交信息写清"做了什么 + 验收门结果"；
- 不提交 `local.properties`、`*.jks`、`build/`；
- 每步结束在 `05-验收清单.md` 填一行记录（日期 + 结果），失败也填。

## 5. 关键实现决策（写死在 M1，避免中途摇摆）

| 决策 | 选择 | 理由 |
|---|---|---|
| 依赖注入 | 手工 `AppContainer` | Hilt 要给 6 个类加注解 + kapt 双跑，自用项目不值得；M1 只有 ~20 个对象 |
| 导航 | `navigation-compose` + 字符串路由 | 5 屏 2 面板，字符串足够 |
| 模型通道 | OkHttp 直连 + 手写 SSE | 不用 Retrofit：只调一个 `/chat/completions`，SSE 手写 40 行可控 |
| JSON | kotlinx-serialization + 自定义容错清洗 | LLM 输出必然脏，需要自己的括号配平逻辑（`04 §6`） |
| 状态 | ViewModel `StateFlow`（不用 Channel 做 UI 状态） | 流式文本用 `MutableStateFlow<String>` 追加；事件用 `TurnOutcome` Flow |
| 流式落库 | 先落用户消息 → 流结束再落 AI 消息 | 中途崩了也不会丢我的回答 |
| 时间 | `Clock` 注入（不用 `System.currentTimeMillis()` 散落） | 单测可固定时间 |
| 日志 | `Logx` 自研接口，debug 写文件 | 亲友闪退要给日志（方案 §七.3）；Level 由 BuildConfig 控制 |
| 密钥 | `MasterKey` + `EncryptedSharedPreferences`（security-crypto 1.1.0） | 方案 §五；**不进 DataStore、不进日志** |

## 6. 风险与预案（M1 阶段）

| 风险 | 触发信号 | 预案 |
|---|---|---|
| 提示词在手机上跑不出"追问"效果 | S5 跑起来后 AI 每轮换题 | 把 `engine_system.md` 的"追问优先"提到最前 + 给一条 few-shot 反例（只答 1/3 时怎么追）；用同一题在 2 个模型上对比，把结果记进 `05 §4` |

| 流式在弱网断掉 | 首字后 10s 无增量 | 超时 90s + 显示"网络慢，已收到 N 字"；断流保留已收内容并允许重试（不重放开头的 token 消耗：重试从上一次 user 消息开始） |

| 手机上打字负担重 | 自己用两次就不想用 | 每题"跳过" + 允许一句话流水账（AI 自己拆）；输入框 3 行起 |
| 场景 JSON 与代码里的 6 个字段不同步 | seed 报错 | `SceneSeedTest` 用真实 asset 跑一次反序列化；JSON `schemaVersion` 字段校验 |
| 中文路径坑复发 | 构建报 `Included build ... does not exist` | 只用 `F:\askfirst`；IDE 也从该路径打开 |
