# M4 施工清单：跨场景引用（搜索 / 勾选注入 / 引用入库 / 溯源）

> 目标（README 里程碑表）：做新方案时能引上个月的立项结论——开工前可检索旧确认单，
> 勾选 ≤3 份注入新一轮提问（只给摘要，防上下文污染），引用关系入库，
> 历史详情页能看出「这份结论基于哪几份旧结论」。

---

## 1. 范围与不做

做：
- 开题页（首页第 2 步下）「带上旧结论（可选）」入口 → 引用选择页。
- 引用选择页：关键词搜索历史确认单（LIKE 全表扫，方案 §五明确不上 FTS）；
  空关键词列最近 30 份；勾选上限 3 份，超过不给勾。
- 开新会话时把勾选的确认单写入 `citation` 表；每一轮提问把**摘要**（`SheetDigest`）
  注入引擎上下文（`EngineContext.referencedSheets`，M1 已预留）。
- 历史详情页显示「这份结论基于哪几份旧结论」，每行可点进被引会话的详情。
- 数据库 v1→v2 显式迁移（只加 `citation` 表；M2 未用的 `lastReadAt` 不再补，见偏差 1）。

不做（留给后续）：
- 反向溯源（这份旧结论被谁引用过）——个人数据量下价值低。
- 引用的增删（会话开始后不能改引用）——改主意就重开一场，成本低。
- 按确认单单条条目粒度引用——整份摘要粒度已够（省 token 是方案 §3.4 的硬要求）。

## 3. 关键决策

1. **只注入摘要不注入全文**（方案 §3.4）：`SheetDigest(sceneId, summary, createdAt)`
   进 `EngineContext.referencedSheets`；`PromptBuilder` 已有渲染段
   （「只作背景，不许拿它替他回答」），M4 不改提示词。
2. **勾选上限 3 份在 UI 和 facade 双拦**：picker 里第 4 份不给勾；`start` 里
   `CitationPolicy.cap` 再截一次（防止将来别的入口绕过 UI）。
3. **搜索候选 = 有单子的会话（每会话最新一张）**：没出过单的会话没有可引的结论。
   关键词 LIKE 命中三处：会话摘要、最初那句话、单子摘要；`%`/`_` 先清洗（ESCape 转义烦，
   直接删掉这两个字符——它们在中文输入里没有正当用途）。
4. **空关键词 = 最近 30 份**：几百条量级的个人数据，翻最近往往比想关键词快。
5. **citation 表不加外键**：工程其余 6 张表也没用 FK（删会话功能不存在，
   不会产生悬空引用；真出悬空行 UI 容错跳过）。与既有风格一致。
6. **场景删除的引用检查不需要扩展**（M3 验收 §7 的疑虑）：citation 引用的是 sheet
   （属会话），不直接引用 scene；`countByScene` 拦的「会话还在」已经把整条链保住了。
7. **迁移 v1→v2 只建 citation 表**：docs/03 原计划 v2=M2 `lastReadAt`，M2 实际没用上
   （历史列表用 `updatedAt` 排序就够），不再补一个空列——少一次无意义迁移风险。
8. **界面零内部词**：不出现 citation/digest/LIKE；引用叫「带上旧结论」，
   溯源区块叫「这份结论基于哪几份旧结论」。

## 4. 施工顺序

- S1 域层纯函数（先测后写）
- S2 数据层（实体/DAO/迁移/仓库）
- S3 门面 + 引擎接线（`referencedSheets`）
- S4 UI + 导航（picker / 首页 / 提问流 / 历史详情）
- S5 单测全绿 + 构建门
- S6 真机验收（M4-01~M4-10，见 docs/05 追加段）+ 收口文档
