# AskFirst 提问引擎契约与提示词规范（M1）

> 这是 M1 唯一的"难"部分。目标不是"把模板题念完"，而是：**问得准、追得深、不编造、随时能停。**
> 依据：方案 §3.1 三条硬规则 + 笔记 12 条改动（本文件负责 #1/#2/#5/#9/#10/#11，#3/#4/#12 的状态与表结构见 03）。

---

## 1. 一轮请求的上下文组装（不分层委托 —— 改动 #10）

`grill-with-docs` 的公开教训是"部分加载"：SKILL 只给一行委托，依赖没全加载时会退化成"一次问完所有题、
且没有推荐答案"。所以 **每次请求都把引擎规则、场景清单、出单规则放进同一个 messages 数组**，不靠多次调用。

```
messages[0] system  = prompts/engine_system.md          （人设 + 硬规则 + 输出 schema + 六问法 + 禁用选题）
messages[1] user    = <组装块>                            （见下，纯结构化文本，不塞散文）
```

`<组装块>` 固定 6 段，缺哪段就写"（空）"，顺序不许变：

```
## 用户最初那句话
<intent>

## 当前场景：<scene.name>
关注点：<scene.focus>
问题清单（id | 必问/选问 | 是否条件题 | 问题 | 为什么问）：
tech_q1 | 必问 |  | 这次要解决什么问题？… | 先钉住痛点…
...

## 已覆盖问题 id
tech_q1, tech_q4          ← 空则写（无）

## 会话全文（最近 N 轮，超长从最早处截断并标注）
[U] 用户：…
[A] AI：…（问题：tech_q3）
...

## 确认单草稿（实时生长，改动 #6）
1 目标与成功标准：
  - …
2 约束与前提：
  - …
（空栏写"（空）"）

## 当前状态（内部用，不许在回答里出现这些词）
state = needs_precision
待处理的精确度缺口：hidden_default: "同步" 暗含云端（来自 U12）
```

### token 预算（M1 硬指标）

| 块 | 上限 | 超了怎么办 |
|---|---|---|
| system | ~1200 token | 提示词本身要瘦；六问法只留示例短句 |
| 场景清单 | ~800 token | 超过 12 题的场景，按 required + 未覆盖优先截断（M3 才有超长场景） |
| 会话全文 | ~3000 token | 从最早处整轮丢弃，保留首轮 intent 与最近 6 轮 |
| 单轮输出 | `max_tokens: 1200` | 输出 JSON，不写散文 |

`temperature = 0.6`（提问要稳，但别死板）；`response_format = {"type":"json_object"}` 若服务端支持则带上，
不支持时靠提示词 + 容错解析（第 6 节）。

## 2. 一轮输出契约（`EngineTurnPayload`）

```json
{
  "state": "gathering | needs_precision | blocked | ready",
  "clarify": "一行复述我理解到的你上一轮意思（不评价、不夸奖）",
  "covered": ["tech_q1"],
  "questions": [
    {
      "id": "tech_q2",
      "text": "时间、人力、预算、必须复用的现有系统——哪一条是硬的？",
      "why": "边界不清的话，候选方案没法比较",
      "kind": "open",
      "recommended": "我猜是时间和必须复用的旧系统这两条最硬，对吗？",
      "options": []
    }
  ],
  "sheet_delta": [
    { "col": 1, "text": "把首屏加载从 4s 降到 1s 以内", "source_message_ids": ["m_03"] }
  ],
  "precision_issues": [
    { "kind": "hidden_default", "target": "col2", "detail": "「同步到手机」暗含云端存储，未确认", "quoted": "顺手同步到手机就行" }
  ],
  "nudge": "再聊 1 个问题就能出单了",
  "block_reason": null
}
```

字段纪律：

| 字段 | 规则 |
|---|---|
| `state` | 由模型给出建议，**服务端/本地用 `StateMachine` 复核**（模型说 ready 但第 4 栏不足 2 条 → 打回 needs_precision） |
| `clarify` | 必须复述上一轮答案；预填的假设也必须显式说明"我按…理解，对吗"（笔记 §四） |
| `covered` | 只列"用户已经明确回答了"的 id；含糊提到不算覆盖 |
| `questions` | 一轮 **1~3 题**（软建议，不是硬上限——改动 #1：题数不进逻辑，只在提示词里建议"一次 1~3 题、最难放最后"） |
| `questions[].recommended` | **每题必须给**（grill-me 原文：每个问题附上你推荐的答案）。推荐理由要引用用户说过的话 |
| `questions[].options` | **默认空数组** = 开放式输入。只有"答案真的对应不同取舍方向"时才给 2~4 个选项，且 UI 强制追加「我自己写」（改动 #2） |
| `sheet_delta` | 本轮回答能填进五栏的内容；**每条必须带 `source_message_ids`**，指向用户发言的消息 id；没有出处的条目不入库（D4） |
| `precision_issues` | 只在 `state != gathering` 时给；`kind ∈ hidden_default / contradiction / walkthrough_gap / goal_drift` |
| `nudge` | 软提示，可以没有；**绝不允许**当停止信号 |
| `block_reason` | `state = blocked` 时必填，且用**用户的话**说明冲突（"你说不用登录，又说每人只看自己的，这两条不能同时成立"） |

**禁止出现在输出里**：`门槛`、`状态机`、`精确度缺口`、`修复`、`轮次`、`covered`、`schema` 这些内部词（改动 #11）。
用户词汇必须镜像：他说"记一下"，你就用"记"，不许改成"录入"。

## 3. 出单契约（`SheetPayload`，`够了` 后单独一次调用）

```json
{
  "summary": "把首屏 4s 降到 1s，先做缓存分层，不引 CDN",
  "columns": {
    "1": ["目标：首屏 P90 从 4.0s → 1.2s", "成功标准：灰度 10% 用户 3 天内无回滚"],
    "2": ["约束：只有 1 个后端人力，两周内上线", "前提：现有 Redis 集群可复用"],
    "3": ["选定：本地缓存 + 接口聚合层", "放弃 CDN：海外节点成本超预算（用户原话：预算最多三万）"],
    "4": ["今天：拉现有首屏接口的耗时火焰图", "本周：给聚合层定接口契约，写一页 ADR"],
    "5": ["还没定：缓存失效策略用 TTL 还是主动通知", "没确认：DAU 峰值是否含大促"]
  }
}
```

- 每栏是**条目数组**（手机读得动）；第 4 栏 **≥2 条**具体动作，动词开头。
- 第 5 栏必须保留"没想清楚/没确认"的原样，**不许改写成"后续持续优化"**。
- 出单前本地先跑 `SheetValidator`：第 4 栏 <2 条 → 返回 `blocking`，UI 显示"这份单子还不能直接开工：第 4 栏只有 1 条动作"，
  允许用户继续答或强行保存（保存时标记 warning）。
- 出单的 `sheet_delta` 走同一套 `SheetGrower`，保证出处齐全；出单 JSON 里**没有** `source_message_ids` 时，
  按"当前轮用户消息"兜底——**但只在条目文本能在该消息里找到对应片段时才允许兜底**，否则丢弃该条（宁缺不编）。

## 4. 状态机（改动 #3）

四个状态，**只用于引擎内部与数据层**，界面永不显示这些词。

| 状态 | 进入条件 | 引擎行为 |
|---|---|---|
| `gathering` | 还有必问题未回答/未覆盖 | 问当前最重要的缺口；按决策树优先级挑，不按 1..n 线性问 |
| `needs_precision` | 必问题都有答案，但精确度四项检查未过 | 只追问精确度缺口，**不开新维度** |
| `blocked` | 冲突 / 「都要」未收敛 / 「你决定」未确认 / 隐含危险假设 | 只处理阻断，把两句原话并排引出来问"哪个是你真正要的" |
| `ready` | 必问齐 + 精确度全过 + 无阻断 | 允许出单；**仍然不强制停止**，停止权永远在用户 |

转移规则（`StateMachine.evaluate` 实现，单测覆盖）：

```
gathering        → gathering | needs_precision | blocked
needs_precision  → needs_precision | blocked | ready      （不许跳 ready 除非四项全过）
blocked          → blocked | gathering                    （解决后回到收集，不直接 ready）
ready            → ready | gathering                      （用户改已确认内容 → 回退 gathering）
```

**决策树优先级**（笔记 §2.1）：痛点没清楚，后面全无法判断；「主动作」依赖「用户/场景」；
「范围边界」在主功能定了才自然产生。落到 M1 的实现：引擎在挑下一题时按"依赖层级"排序
（`痛点/目标` → `用户/场景` → `主动作` → `范围边界` → `资源/退路`），层级写在 `question.order` 之外的另一列？
**M1 不新增列**，用场景 JSON 里的 `order` 顺序 + 提示词里显式写明层级让模型判断；M3 编辑器再加 `priority` 字段。

## 5. 精确度四项检查（改动 #4，出单前必跑，**离线可跑**）

`PrecisionGate.check(...)` 是纯 Kotlin（无模型、无 Android），逐项返回 `PrecisionIssue`：

| # | 检查 | 实现方式（M1 可落地的版本） | 不过时的追问 |
|---|---|---|---|
| 1 | **目标一致性** | 第 1 栏与 intent 的关键词集合比对：intent 里的实词若在第 1 栏完全消失（或出现近义替换），记 `goal_drift` | "你说的是 A，单子里写成了 B，是同一个东西吗？" |
| 2 | **隐藏默认值** | 扫全部用户回答，命中歧义词表（保存/同步/分享/通知/登录/云端/数据库/推送/管理/记录/简单）→ `hidden_default` | "「保存」是指存本地文件，还是存数据库？" |
| 3 | **场景走查** | 检查第 3 栏是否有"选定方案"，且第 4 栏动作能否串成一条可执行序列（≥2 条、含"打开/进入"这类起点） | "从打开到结果出现，中间有没有一步没定？" |
| 4 | **矛盾扫描** | 规则对：`不登录/无账号` × `每人/各自/我的`；`不要云` × `远程/多端`；`最简单` × `还要/以及` | "这两句放一起不成立：… 哪个是你真正要的？" |

歧义词表与规则对写在 `domain/prompt/Lexicon.kt`（纯数据，可单测）：

```kotlin
object Lexicon {
    /** 一个词 → 该词可能指代的几种意思（追问时二选一，不许开放式泛问） */
    val ambiguous: Map<String, List<String>> = mapOf(
        "简单" to listOf("功能少", "步骤少", "界面干净"),
        "保存" to listOf("存本地文件", "存数据库", "存云端"),
        "同步" to listOf("多设备实时同步", "只是备份", "定时上传"),
        "分享" to listOf("发链接", "发文件", "截图"),
        "管理" to listOf("增删改查", "批量操作", "只是看得清"),
        "通知" to listOf("系统推送", "App 内提醒", "邮件"),
    )

    /** 矛盾规则对：两句同时出现即冲突 */
    val contradictions: List<ContradictionRule> = listOf(
        ContradictionRule(a = "不(用|需要)?登录|无账号", b = "每个人?|各自|我的"),
        ContradictionRule(a = "不要云|纯本地|不联网", b = "多端|远程|同步"),
        ContradictionRule(a = "最简|最简单|功能越少越好", b = "还要|以及|顺便"),
    )
}
```

模型也会输出 `precision_issues`，但**离线 Gate 的结果与模型结果取并集**：模型漏掉的，Gate 补；
模型多说的，进第 5 栏而不是当阻断。

## 6. 解析与容错（LLM 输出 JSON 的现实处理）

```kotlin
class TurnParser(private val json: Json) {
    fun parse(raw: String): AppResult<EngineTurnPayload>
}
```

顺序：

1. 剥 markdown 代码围栏（` ```json … ``` `）；
2. 取第一个**配平**的 `{…}`（自己写括号计数器，跳过字符串内的括号）；
3. 修常见毛病：尾逗号、单引号键、`null` 写成 `"null"`；
4. `Json { ignoreUnknownKeys = true; isLenient = true; coerceInputValues = true }` 反序列化；
5. 失败 → 引擎层**重试一次**：把原始输出 + "只输出合法 JSON，不要解释" 追加上去，温度降到 0.2；
6. 再失败 → `AppError.BadJson(raw, reason)`，UI 显示"模型这次没按要求回，重试一次"，并把原文留在会话里（可回看）。

**永不**在解析失败时静默给一个空 decision —— 那会让用户以为"AI 罢工了"。

出单同理：`SheetParser` 复用同一套清洗，额外要求 5 个栏位都存在（缺栏 → 该栏给空数组 + warning）。

## 7. 六种问法（改动 #5，写进 system prompt 的原样内容）

| 问法 | 何时用 | 提示词里的示例 |
|---|---|---|
| 具象化 | 用户说了抽象词 | "上次你觉得这事很烦的那个**瞬间**，具体发生了什么？" |
| 反面定义 | 正面需求太宽泛 | "做出来你只用一次就不想用了，最可能的原因是什么？" |
| 假设暴露 | 话里藏着未检验前提 | "你说『同步到手机』——是真的会在手机上操作，还是只怕电脑上丢？" |
| 取舍逼问 | 列了多个目标 | "做 A 两天能用，A+B 两周。还都要吗？" |
| 后果推演 | 给了答案没想过下一步 | "假设你存了所有记录，三个月后怎么找到要的那条？" |
| 对比锚定 | 模糊到无法直接追问 | "这跟你现在用备忘录记，最大区别在哪？" |

提问纪律（同样逐条进 prompt）：

- 回答仍然抽象 → **不换话题，换问法再挖同一个点**；
- 说"都要" → 先构造代价场景，再让他选；
- 说"你决定" → 给推荐 + **用他自己的场景解释** + 等确认；
- 答案冲突 → 把两句原话并排引出来，只问"哪个是你真正要的"；
- 不问实现细节，除非直接影响体验且用户能理解；
- **不问用户不可能回答的问题**；
- 推荐理由必须引用用户说过的话；
- 想法太薄 → **主动停下直说**（"现在这套想法还撑不起一份单子，我们先把痛点说具体"），不硬凑轮数；
- 答"不知道" → 记进第 5 栏，不继续推。

## 9. 引擎接口（Kotlin 签名，`domain/engine/`）

```kotlin
class QuestionEngine(
    private val provider: LlmProvider,
    private val prompts: PromptBuilder,
    private val parser: TurnParser,
    private val stateMachine: StateMachine,
) {
    /** 流式：只发"进度"，收尾时给出结构化 decision。**绝不把 JSON 原文吐给 UI** */
    fun turn(ctx: EngineContext): Flow<TurnEvent>
}

sealed interface TurnEvent {
    /** 已收到的字符数，用来显示"正在想…（已收到 37 字）"；不是要显示的正文 */
    data class Progress(val receivedChars: Int) : TurnEvent
    data class Decided(val decision: EngineDecision, val rawJson: String, val assistantText: String) : TurnEvent
    data class Failed(val error: AppError, val rawText: String?) : TurnEvent
}

data class EngineContext(
    val scene: Scene,
    val intent: String,
    val state: EngineState,
    val covered: Set<String>,
    val turns: List<Turn>,                 // 已落库的完整问答
    val draftColumns: Map<Int, List<String>>,
    val pendingIssues: List<PrecisionIssue>,
    val referencedSheets: List<SheetDigest> = emptyList(),   // M4 用，M1 恒空
)

data class EngineDecision(
    val state: EngineState,
    val clarify: String?,
    val covered: Set<String>,
    val questions: List<EngineQuestion>,
    val sheetDeltas: List<SheetDelta>,
    val issues: List<PrecisionIssue>,
    val nudge: String?,
    val blockReason: String?,
)

data class EngineQuestion(
    val id: String,
    val text: String,
    val why: String,
    val kind: QuestionKind = QuestionKind.OPEN,
    val recommended: String? = null,
    val options: List<String> = emptyList(),
)

data class SheetDelta(val col: Int, val text: String, val sourceMessageIds: List<String>)
```

`QuestionEngine.turn` 内部步骤固定 7 步（单测按步骤打桩）：

1. `prompts.engineMessages(ctx)` → messages
2. `provider.stream(req)` → 累积全文 + 同时 `emit(Progress)`（只给进度，不给 JSON 原文）
3. 流结束 → `parser.parse(full)`；
4. 失败 → 一次低温柔性重试（第 6 节第 5 步）；
5. `stateMachine.evaluate(...)` 复核模型给的 state；
6. `covered` 与场景清单求交（模型编造的 id 丢弃，不报错）；
7. `emit(Decided)`。
