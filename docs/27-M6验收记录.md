## 4. 真机上发现并修掉的缺陷（验收驱动）

1. **代理失败回退把 500 盖成「token 不认」**（P1）：`FetchOutcome.Failed` 原来没有「是不是连不上」的标记，
   回退条件写成了「只要失败就直连试一次」——假服务回 500，回退打到真 GitHub 返回 401，
   最终报的是「GitHub 不认这个 token」，把真实原因盖掉了。修：`Failed` 加 `connection` 标记，
   **只有连接层失败才回退**；两条路都不通时把两边原因都写上。补 1 个单测（M6-07 现场发现）。
2. **60s 预算不是真的硬**（P1）：原来只在「问题之间」看预算，一个卡住的请求（重试 3 次 × 30s 调用超时）
   能把 60 秒拖成 90 秒。修：整段取证包进 `withTimeoutOrNull(budgetMs)`，超时用手里的证据出残本；
   剩余预算不够时**不再发起模型对照**，报告里写明「没来得及对照」。
3. **确认单页从调研页返回不刷新「调研补充」**（P2）：查完退回来，第 2/5 栏下面还是空的，用户会以为白查了。
   修：`LifecycleResumeEffect` 回页即重读（M6-10 现场发现）。
4. **断网预判把「没有活动网络」判成有网**（P2）：`ConnectivityManager.activeNetwork` 为 null 时回落成了
   `true`，于是飞行模式下照样白等重试。修：没有活动网络就是没网，只有「服务拿不到」才当有网（M6-15 现场发现）。
5. **立题把正常问题误杀**（P2）：内部词黑名单里带了 `json`，而「把确认单存成单个 JSON 会不会被并发写坏」
   是一句完全正常的问题，被整条丢掉，导致只剩 2 个问题还触发了兜底。修：黑名单只留我们自己的实现词
   （verdict/evidence/research/prompt/sectionsJson/planSkeleton/sessionId）。

## 5. 决策与偏差（相对 docs/26）

1. **`appliedTo` 由机械层分配**（不跟模型走）：反模式/常见做法 → 第 2 栏；已知坑/无人区 → 第 5 栏；未取证 → 只进附录。
   页面只能在这三个里切，第 3 栏没有入口（枚举 + 库 CHECK 双层）。
2. **「通用搜索复核」换成「换词复核」**：不上第三方搜索引擎，用「原句 + 关键词单发」再检索 GitHub；
   仍然 0 命中才算无人区。少一个不受控的抓取面，而且换词再查本来就是这条结论缺的证据。
3. **复制为提示词不带调研结论**：提示词给下游模型干活，把「别人怎么做」塞进去正是要防的决策污染；
   M1 的六行模板**逐字未动**（`PromptExporterTest` 继续锁着）。结论只出现在确认单页「调研补充」与报告里。
4. **证据不进 `sheet_item`**：条目必须有原话出处这条铁律没破（`sourceMessageIds='[]'` 仍 0 行），
   查来的东西挂在第 2/5 栏下面的只读区块里。
5. **离线外包要「证据 + 判定」一起回**：只回判定会出现「引用了不存在的链接」，那比没有报告更糟。
6. **对照上下文里的证据上限 40 条**，超出时上下文里明说「还有 N 条没列出来」。
