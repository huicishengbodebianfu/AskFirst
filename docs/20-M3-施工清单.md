# M3 施工清单：场景编辑器 + 自建场景 + JSON 导入导出

> 目标（README 里程碑表）：让用户能**自己造场景**——3 套出厂场景不够用时，
> 在手机上新建/编辑一套自己的问题清单；能把场景导出成 JSON 分享给别人，别人一键导入。
> 数据全本地，格式与 `assets/scenes/*.json` 完全一致（`SceneSeed` 本来就是为 M3 设计的交换格式，docs/03 §5）。

---

## 1. 范围与不做

做：
- 新建场景（名称 + 一句话定位 + 问题清单：题目/为什么问/是否必问/条件触发词）。
- 编辑**自建**场景；内置场景不可改（升级会被种子覆盖，改了必丢），提供「复制为自建」。
- 删除自建场景（有会话引用时拒绝并说明）。
- 导出：任意场景 → JSON 文本 → 系统分享面板（复用 M2 的 `ACTION_SEND` 套路）。
- 导入：系统文件选择器选 `.json` → 容错解析 + 校验 → 落库为自建场景；id 撞车自动换新 id。

不做（留给后续）：
- 拖拽排序（用「上移」按钮代替）。
- 场景图标/颜色。
- planSkeleton 编辑（M5 才用；导入导出时原样保留）。

## 2. 分层落位

| 层 | 文件 | 内容 |
|---|---|---|
| 域 | `domain/model/SceneDraft.kt` | 草稿模型 + `validate()`：可读中文校验（名称非空、定位非空、≥1 题、题干/为什么问非空、trigger 正则必须能编译、题数 ≤ 30） |
| 域 | `domain/scene/SceneJsonCodec.kt` | `decode(text): AppResult<SceneSeed>`（复用 `AppJson` 容错：未知字段忽略、单引号、字符串化 null；校验失败给中文错误）＋ `encode(scene): String`（字段顺序稳定，人可读缩进）＋ `resolveImportId(seed, existingIds)`（撞车换新 id，纯函数） |
| 数据 | `data/repo/SceneRepository.kt` | `create/update/delete/importScene/duplicate/exportJson`；builtin 只读；写库沿用 seeder 的「先删后插」 |
| 数据 | `data/db/dao/SessionDao.kt` + `SessionRepository` | `countByScene(sceneId)`：删除前的引用检查 |
| 门面 | `AskFirstFacade` | `createScene/updateScene/deleteScene/importSceneJson/exportSceneJson/duplicateScene/sceneOf` |
| UI | `ui/screens/scene_edit/`（3 文件） | `SceneEditScreen` + ViewModel + UiState |
| 导航 | `Route.kt` / `AskFirstAppRoot.kt` | `scene_edit?sceneId={id}`（空 = 新建） |
| 首页 | `HomeScreen.kt` | 场景区头部「自建场景 / 导入」；每张卡右上 ⋮ 菜单：自建 → 编辑/导出/删除；内置 → 复制为自建/导出 |

## 3. 关键决策

1. **内置场景不可编辑/删除**：`BuiltinSceneSeeder` 每次启动按 id 覆盖 builtin 场景（幂等设计），
   用户改内置必被冲掉。UI 上内置卡的菜单只有「复制为自建 / 导出」。
2. **导入 id 撞车自动换 id**，不改名字（朋友间传场景最常见的失败就是 id 一样）；
   导入进来的永远是 `builtin=false`。
3. **删除被会话引用的场景会被拒绝**：历史详情按 sceneId 关联场景，删了历史就残废。
   错误文案说清「先用它聊过的会话还在」。
4. **问题排序用 order 字段重排**：编辑器里「上移」一次，保存时按当前列表顺序 1..n 重写 order。
5. **界面零内部词**：不出现 schemaVersion/trigger/JSON 等字样，trigger 叫「问到这个词才出现」。

## 4. 施工顺序

- S1 域层（纯 JVM，先写测试再写实现）
- S2 数据层
- S3 门面
- S4 UI + 导航
- S5 单测全绿 + 构建门
- S6 真机验收（M3-01~M3-12，见 docs/05 追加段）+ 收口文档
